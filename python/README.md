# petsird_validation

Checks a PETSIRD file against the rules of the
[PETSIRD model](https://github.com/ETSInitiative/PETSIRD).

yardl checks the types when a PETSIRD file is written, but many rules of the
model exist only as `# Constraint:` comments in the model YAML files
(`model/*.yml` in the PETSIRD repository). A file can be read back without
errors and still break those rules. This package checks them.

## Install

Use an environment that has `petsird` installed (for example the conda
environment from `environment.yml` in the repository root), then:

```sh
cd python
pip install -e .
```

## Usage

```sh
petsird-validator my_scan.petsird
petsird-validator my_scan.petsird --max-blocks 100  # only the first 100 time blocks
```

```
  20 passed · 5 failed · 5 skipped · 1 with warnings
  5 of 25 checks failed
```

In a terminal, PASS is green, FAIL red, WARN yellow and SKIP grey, and the
summary bar has one square per check in those colours. Colours are off when
the output goes to a file or pipe, or when `NO_COLOR` is set; `--color always`
or `--color never` overrides this.

While the time blocks are read, a progress bar shows how far through the file
the reader is (or how many of the N blocks with `--max-blocks`), with the time
taken so far and an estimate of the time left:

```
  reading time blocks ███████████████░░░░░░░░░░░░░░░  48% · 29,112 blocks · 1m 10s · ~1m 16s left
```

It appears only in a terminal, on stderr, and is removed when reading ends.

The results are grouped by stage, then by the model file each check comes
from. The checks run in three stages:

- header checks, once;
- time-block checks, on every time block of the type they check. Each shows
  how many blocks it checked and, if it failed, in how many blocks and where
  the first failure is;
- stream checks, once at the end, on a summary of all the time blocks (for
  example, that dead-time blocks cover all event time).

A check with nothing to run on is shown as `SKIP` and not counted. The stream
checks are skipped with `--max-blocks`, because the stream may not have been
read to the end. `WARN` lines come from soft checks and don't change the exit
code.

Binary and NDJSON PETSIRD files are supported. HDF5 files are not, because
the Python SDK generated by yardl has no HDF5 reader.

Exit codes: `0` all checks pass, `1` at least one check failed, `2` the file
could not be read.

The checks can also be called from Python, on a header read from a file or
built in memory:

```python
import petsird
from petsird_validation.detector_information import validate_material_ids

with petsird.BinaryPETSIRDReader("my_scan.petsird", skip_completed_check=True) as reader:
    header = reader.read_header()

validate_material_ids(header)  # raises ValueError if a constraint is broken
```

## Layout

There is one module per file in PETSIRD's `model/` folder. Each `validate_*`
function raises `ValueError` at the first broken constraint, and its docstring
names the model file and field it checks. Soft checks call `_common.warn`,
which shows as a `WARN` line. The tables below list every check: what it runs
on, the constraint it enforces, and the broken test files in
`tests/broken_files.py` that make it fail. T is the number of module types.

### DetectorInformation.yml: `detector_information.py`

| Check | Runs on | Constraint | Broken test files |
| --- | --- | --- | --- |
| `validate_scanner_geometry` | header | `scannerGeometry.replicatedModules` is not empty (T > 0) | `no_module_types` |
| `validate_detecting_elements` | header | the crystal box of each module type lies along +x, with the front face nearest the scanner centre, and contains (0,0,0), the average detection position | `crystal_facing_backwards`, `crystal_shifted_along_z`, `crystal_in_front_of_adp` |
| `validate_material_ids` | header | every `materialId` (crystals, non-detecting elements, `nonDetectingVolumes`) is the id of an entry in `bulkMaterials` | `unknown_crystal_material`, `unknown_plate_material`, `unknown_non_detecting_volume_material`, `no_bulk_materials` |

### GeometryInformation.yml: `geometry_information.py`

| Check | Runs on | Constraint | Broken test files |
| --- | --- | --- | --- |
| `validate_box_shapes` | header | in every `BoxShape`, the 4 corners of the front face and of the back face are clockwise, and the first is the smallest in (z, y, x) order | `crystal_face_counterclockwise`, `crystal_face_starts_at_wrong_corner`, `plate_face_counterclockwise` |
| `validate_replicated_objects` | header | every `ReplicatedObject` (module types, crystals, non-detecting elements) has at least one transform | `module_type_without_modules`, `module_without_crystals`, `plate_without_transforms` |
| `validate_transforms` | header | every `RigidTransformation` (modules, crystals, non-detecting elements, `gantryAlignment`) is finite, with an orthonormal rotation part with det +1 | `scaled_module_transform`, `mirrored_crystal_transform`, `nan_in_plate_transform`, `sheared_gantry_alignment` |

### MaterialInformation.yml: `material_information.py`

| Check | Runs on | Constraint | Broken test files |
| --- | --- | --- | --- |
| `validate_material_ids_unique` | header | the `bulkMaterials` ids are unique | `duplicate_material_id` |
| `validate_material_fraction_count` | header | `size(atoms) == size(massFractions)` for every material | `atom_without_mass_fraction` |
| `validate_material_fraction_sum` | header | the `massFractions` of every material are finite and sum to 1 (within 1e-6) | `mass_fractions_not_summing_to_one` |

### ScannerInformation.yml: `scanner_information.py`

| Check | Runs on | Constraint | Broken test files |
| --- | --- | --- | --- |
| `validate_bin_edges` | header | every `BinEdges` (`tofBinEdges`, `eventEnergyBinEdges`, `singlesHistogramEnergyBinEdges`) has at least 2 edges, all finite and strictly increasing | `decreasing_energy_bin_edges` |
| `validate_scanner_array_dimensions` | header | `tofBinEdges`, `tofResolution`, `eventEnergyBinEdges` and `energyResolutionAt511` have T entries; rows of `tofBinEdges` and `tofResolution` have i+1 entries (T entries are also accepted) | `missing_energy_resolution` |
| `validate_scanner_resolutions` | header | `tofResolution` and `energyResolutionAt511` are finite and > 0 | `zero_tof_resolution` |
| `validate_singles_histogram_dimensions` | header | `moduleSinglesUnitIdxLUTs` and `singlesHistogramEnergyBinEdges` agree with `singlesHistogramLevel`: NONE, both empty; ALL, no LUTs and at least T edge lists; MODULE, T LUTs and at least T edge lists | `singles_luts_with_level_none` |
| `validate_collimator_type` | header | `collimatorType` is `NONE` or `RING` | `unknown_collimator_type` |

### DetectionEfficiencies.yml: `detection_efficiencies.py`

Note that the model allows any of these components to be empty ("its value is
considered to be 1"), which the dimension checks don't accept yet: a file that
leaves out the efficiencies fails them.

| Check | Runs on | Constraint | Broken test files |
| --- | --- | --- | --- |
| `validate_detection_bin_efficiency_dimensions` | header | `detectionBinEfficiencies` has T entries | `missing_detection_bin_efficiencies` |
| `validate_number_module_types_consistency` | header | `detectionBinEfficiencies` has T entries | `missing_detection_bin_efficiencies` |
| `validate_module_pair_sgid_dimensions` | header | `modulePairSGIDLUT` and `modulePairEfficienciesVectors` have T rows; row i has i+1 entries (T entries are also accepted) | `missing_sgid_lut_row` |
| `validate_sgid_ranges` | header | SGIDs are at least -1; `modulePairEfficienciesVectors[i][j]` has max(SGID)+1 entries, and entry k has `sgid` k | `wrong_sgid_in_efficiencies` |
| `validate_efficiency_values` | header | `calibrationFactor`, `detectionBinEfficiencies` and the module-pair efficiency values are finite | `nan_detection_bin_efficiency` |

### SinglesHistograms.yml: `singles_histograms.py`

| Check | Runs on | Constraint | Broken test files |
| --- | --- | --- | --- |
| `validate_singles_unit_luts` | header | with `singlesHistogramLevel` MODULE, `moduleSinglesUnitIdxLUTs[t]` has one entry per module, all at least -1; warns if no module has a singles unit | `singles_unit_below_minus_one`, `module_type_without_modules` |

### ExamInformation.yml: `exam_information.py`

| Check | Runs on | Constraint | Broken test files |
| --- | --- | --- | --- |
| `validate_exam` | header | the `exam.externalSignals` ids are unique; warns if `modality` is not `PT` | `duplicate_external_signal_id` |

### DICOMTypes.yml: `dicom_types.py`

| Check | Runs on | Constraint | Broken test files |
| --- | --- | --- | --- |
| `validate_patient_information` | header | `exam.patient`: `patientsSex` is `M`, `F`, `O` or empty; `patientsSize`, `patientsWeight` and `patientsBodyMassIndex` are finite and at least 0 | `invalid_patient_sex`, `negative_patient_weight` |
| `validate_patient_orientation` | header | the 3 code sequences of `exam.patientOrientation` are valid (see `validate_dicom_code_sequences`) | `orientation_code_without_scheme` |
| `validate_radiopharmaceutical_information` | header | for each of `exam.radiopharmaceuticals`: volume, total dose and specific activity are finite and at least 0; the stop time is not before the start time; the administration event UID is a valid DICOM UID | `radiopharmaceutical_stops_before_it_starts` |
| `validate_dicom_uid` | header | every field whose name ends in `uid` is empty or a valid DICOM UID: at most 64 characters, numbers separated by dots, no leading zeros | `invalid_study_instance_uid` |
| `validate_dicom_code_sequences` | header | in every code sequence (patient orientation, radiopharmaceutical, radionuclide), `codeValue` and `codeValueURN` are not both set, and `codingSchemeDesignator` is set when `codeValue` is | `orientation_code_without_scheme`, `radionuclide_code_value_and_urn` |

### TimeFrameInformation.yml: `time_frame_information.py`

| Check | Runs on | Constraint | Broken test files |
| --- | --- | --- | --- |
| `validate_time_interval` | every time block | `timeInterval.start <= timeInterval.stop` | `bed_movement_ends_before_it_starts` |

### Events.yml: `events.py`

| Check | Runs on | Constraint | Broken test files |
| --- | --- | --- | --- |
| `validate_detection_bins` | event blocks | every detection bin is less than the number of detection bins of its module type (modules × crystals × energy bins) | `detection_bin_out_of_range`, `module_type_without_modules`, `module_without_crystals` |
| `validate_tof_indices` | event blocks | `tofIdx` and `tofIndices` are less than the number of TOF bins of the module-type pair | `tof_index_out_of_range` |
| `validate_singles_times` | event blocks | `timeOffsetInTimeBlock` of every single is within the block (`timeInterval` is in ms, the offset in ps), and blocks with singles are shorter than 2^32 ps | `single_after_block_end` |

### Protocol.yml: `protocol.py`

| Check | Runs on | Constraint | Broken test files |
| --- | --- | --- | --- |
| `validate_event_list_shapes` | event blocks | each event list is empty if its policy is NONE, otherwise nested by module type: singles [T], prompts and delayeds [T][i+1], triples [T][i+1][j+1], quadruples one level deeper | `prompt_rows_repeated`, `delayeds_stored_with_policy_none` |
| `validate_event_order` | event blocks | in each coincidence, `t1 > t2` or `bin1 >= bin2`; triples and quadruples are in non-increasing (type, bin) order | `unordered_coincidence` |
| `validate_event_block_type` | event blocks | blocks are `WeightedEventTimeBlock`s exactly when `containsWeightedEventTimeBlocks` is true | `weighted_blocks_declared_but_not_stored` |
| `validate_weights` | weighted event blocks | every list of weights has the same nested sizes as its list of events | `prompt_weight_missing` |
| `validate_external_signal` | `ExternalSignalTimeBlock` | `signalID` is declared in `exam.externalSignals` | `undeclared_external_signal` |
| `validate_bed_movement` | `BedMovementTimeBlock` | `transform` is rigid | `scaled_bed_transform` |
| `validate_gantry_movement` | `GantryMovementTimeBlock` | `transforms` has one rigid transform per module type | `gantry_movement_for_one_module_type` |
| `validate_singles_histogram` | `SinglesHistogramTimeBlock` | the block is allowed (`singlesHistogramLevel` is not NONE). MODULE: one histogram per singles unit, with as many counts as its modules' singles energy bins, and no per-detection-bin histogram. ALL: one per-detection-bin histogram per module type, of size modules × crystals × singles energy bins, and no per-unit histogram | `singles_histogram_with_extra_energy_bin`, `singles_luts_with_level_none` |
| `validate_dead_time_coverage` | whole stream | the `DeadTimeTimeBlock`s cover all the time of the event blocks | `no_dead_time_blocks` |
| `validate_singles_histogram_coverage` | whole stream | unless `singlesHistogramLevel` is NONE, the `SinglesHistogramTimeBlock`s cover all the time of the event blocks | `singles_histograms_stop_early` |

### Helpers

- `basic_types.py` (BasicTypes.yml): `check_lower_triangular` and
  `check_lower_triangular_or_rectangular` check the shape of the matrix types.
  They are tested in `tests/test_basic_types.py`.
- `_common.py`: `PETSIRDWarning`, `warn()`, and the number of module types,
  modules and detection bins.

### Test suites

Each module registers its checks at the bottom of the file, in a dict named
`<module>_tests_suite` that maps a short description to the check and its
level:

```python
protocol_tests_suite = {
    "event order": {
        "func": validate_event_order,
        "level": "event_block",
    },
    "external signal": {
        "func": validate_external_signal,
        "level": "block",
        "block_types": ("ExternalSignalTimeBlock", ),
    },
    ...
}
```

The level says what the check takes and what it runs on:

| Level | Called as | Runs on |
| --- | --- | --- |
| `header` | `check(header)` | the header, once |
| `all_block` | `check(header, block)` | every time block |
| `event_block` | `check(header, block)` | every `EventTimeBlock` and `WeightedEventTimeBlock` |
| `block` | `check(header, block)` | the time blocks whose types are listed in `block_types` |
| `stream` | `check(header, summary)` | once, on the `protocol.StreamSummary` of all the time blocks |

`cli.py` imports every suite into `TEST_SUITES` and builds from them the lists
of checks it runs (`HEADER_CHECKS`, `ALL_BLOCK_CHECKS`, `BLOCK_CHECKS` by
time-block type, and `STREAM_CHECKS`). A malformed entry stops the command
with a message saying which entry is wrong.

## Tests

```sh
cd python
pip install -e ".[test]"
pytest
```

`tests/broken_files.py` builds a small valid PETSIRD file: a scanner with 2
module types, and a time block of every type (2 event blocks with singles,
prompts and delayeds, external signal, bed and gantry movement, dead time and
a singles histogram). `make_weighted` turns its event blocks into weighted
ones. It also builds broken copies, at least one per check, each breaking
one constraint; the tables in [Layout](#layout) list them by check.

The tests write each file, run `petsird-validator` on it, and check that:

- the valid files (binary, NDJSON and weighted) pass every check;
- each broken file fails exactly the expected checks, with the expected
  message. A broken file for a check the command does not run yet is skipped;
- every check the command runs has at least one broken file;
- every `validate_*(header, ...)` function is registered in its module's test
  suite, with a valid level and the number of arguments that level needs, and
  `cli.py` runs every suite (`tests/test_suites.py`);
- warnings, `--max-blocks`, `--color` and unreadable files behave as described
  above.

To get the files and try them by hand:

```sh
python tests/broken_files.py broken/
petsird-validator broken/broken_crystal_shifted_along_z.petsird
```

## Adding checks for another model file

1. Create a module named after the model file, for example
   `scanner_information.py` for `ScannerInformation.yml`.
2. Write `validate_*` functions that raise `ValueError` with a message saying
   what is wrong and where (and call `_common.warn` for soft checks).
3. At the bottom of the module, register them in `<module>_tests_suite` with
   their level (see [Test suites](#test-suites)). Adding a check to an
   existing module needs nothing else.
4. For a new module, import its suite in `cli.py` and add it to
   `TEST_SUITES`.
5. Add a broken file for each check in `tests/broken_files.py`: a function
   decorated with `@broken("validate_...", match="...")` that changes the
   valid header or time blocks (`data.header`, `data.blocks`).
6. Add a table for the model file in [Layout](#layout).
