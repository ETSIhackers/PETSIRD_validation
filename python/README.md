# petsird_validation

Checks a PETSIRD file against the rules of the
[PETSIRD model](https://github.com/ETSInitiative/PETSIRD).

yardl checks the types when a PETSIRD file is written, but many rules of the
model exist only as `# Constraint:` comments in the model YAML files
(`model/*.yml` in the PETSIRD repository). A file can be read back without
errors and still break those rules. This package checks them.

## Install

Use an environment that has `petsird` installed (for example the conda
environment from `environment.yml` in the repository root), then:

```sh
cd python
pip install -e .
```

## Usage

```sh
petsird-validator my_scan.petsird
```

```
PASS validate_scanner_geometry
PASS validate_detecting_elements
FAIL validate_material_ids: scannerGeometry.replicatedModules[0].object.detectingElements.object.materialId is 1, but bulkMaterials ids are none
PASS validate_box_shapes
PASS validate_replicated_objects
PASS validate_transforms
1 of 6 checks failed
```

Binary and NDJSON PETSIRD files are supported. HDF5 files are not, because
the Python SDK generated by yardl has no HDF5 reader.

Exit codes: `0` all checks pass, `1` at least one check failed, `2` the file
could not be read.

The checks can also be called from Python, on a header read from a file or
built in memory:

```python
import petsird
from petsird_validation.detector_information import validate_material_ids

with petsird.BinaryPETSIRDReader("my_scan.petsird", skip_completed_check=True) as reader:
    header = reader.read_header()

validate_material_ids(header)  # raises ValueError if a constraint is broken
```

## Layout

There is one module per file in PETSIRD's `model/` folder. Each `validate_*`
function raises `ValueError` at the first broken constraint, and its docstring
names the model file and field it checks.

| Model file | Module | Checks |
| --- | --- | --- |
| `DetectorInformation.yml` | `detector_information.py` | `validate_scanner_geometry`: there is at least one module type<br>`validate_detecting_elements`: each crystal box lies along +x and contains (0,0,0), the average detection position<br>`validate_material_ids`: every `materialId` refers to an entry in `bulkMaterials` |
| `GeometryInformation.yml` | `geometry_information.py` | `validate_box_shapes`: the front and back faces of every `BoxShape` are clockwise and start at their smallest corner (order z, y, x)<br>`validate_replicated_objects`: every `ReplicatedObject` has at least one transform<br>`validate_transforms`: every `RigidTransformation` (modules, elements, `gantryAlignment`) is rigid: orthonormal rotation with det +1 |

`cli.py` holds the `petsird-validator` command and the `HEADER_CHECKS` list of
checks it runs.

## Tests

```sh
cd python
pip install -e ".[test]"
pytest
```

`tests/broken_files.py` builds a small valid scanner (2 module types) and
broken copies of it. Each broken copy breaks one constraint. The tests write
every copy to a PETSIRD file, run `petsird-validator` on it, and check that
exactly the expected checks fail with the expected message. A test also
fails if a check in `HEADER_CHECKS` has no broken file.

To get the files and try them by hand:

```sh
python tests/broken_files.py broken/
petsird-validator broken/broken_crystal_shifted_along_z.petsird
```

## Adding checks for another model file

1. Create a module named after the model file, for example
   `scanner_information.py` for `ScannerInformation.yml`.
2. Write `validate_*(header)` functions that raise `ValueError` with a message
   saying what is wrong and where.
3. Add them to `HEADER_CHECKS` in `cli.py`.
4. Add a broken file for each check in `tests/broken_files.py`: a function
   decorated with `@broken("validate_...", match="...")` that breaks the valid
   header.
5. Add a row to the table above.
